# 1. Опис системи, межі та матриця стейкхолдерів

## 1.1. Загальний опис системи (System of Interest)
**Smart Campus & Educational Portal** — це централізована інтеграційна вебплатформа для цифровізації освітнього та адміністративного процесів університету. Система забезпечує єдину точку входу для студентів, викладачів і співробітників деканату, усуваючи фрагментацію між розрізненими обліковими системами закладу.

## 1.2. Бізнес-цілі проєкту
1. **Автоматизація документообігу:** скорочення часу обробки студентських заяв (довідки, індивідуальні графіки, переведення) з 3–5 робочих днів до 24 годин.
2. **Прозорість освітнього процесу:** надання студентам і викладачам актуального доступу до оцінок, відвідуваності та змін у розкладі в режимі реального часу.
3. **Стандартизація контролю знань:** проведення поточного та підсумкового онлайн-тестування з автоматичним перенесенням результатів до електронного журналу.
4. **Зменшення навантаження на адміністративний персонал:** автоматична генерація відомостей та звітів успішності за результатами сесії.

## 1.3. Межі системи (System Scope)

### Входить у межі системи (In-Scope):
* **Модуль розкладу (Schedule Module):** перегляд та оперативне оновлення розкладу занять для академічних груп, викладачів та аудиторій.
* **Електронний журнал (Gradebook Module):** виставлення балів, облік відвідуваності, формування екзаменаційних та залікових відомостей.
* **Сервіс електронних заяв (E-Requests Module):** створення студентами заяв за шаблонами, маршрут погодження через деканат, відстеження статусу.
* **Модуль онлайн-тестування (Assessment Module):** створення тестів викладачами, проходження тестування студентами з обмеженням часу, автоперевірка результатів.
* **Модуль сповіщень (Notification Module):** розсилка повідомлень про зміни у розкладі, нові оцінки та зміну статусу заяв (Email / Web Push / Telegram).

### Не входить у межі системи (Out-of-Scope):
* Бухгалтерський облік, нарахування заробітної плати викладачам та стипендіальний розрахунок (інтеграція відбувається лише через експорт зведених даних).
* Управління фізичним контролем доступу (турнікети в корпусах та гуртожитках).
* Відеохостинг для зберігання записів лекцій (система підтримує лише посилання на зовнішні платформи).

## 1.4. Матриця стейкхолдерів (ISO/IEC/IEEE 42010:2022)

| Роль стейкхолдера | Представник | Ключові занепокоєння (Concerns) | Вплив на архітектуру |
| :--- | :--- | :--- | :--- |
| **End User (Студент)** | Здобувач вищої освіти | Миттєвий доступ до розкладу й оцінок (< 1 с), стабільна робота під час онлайн-тестів без втрати відповідей, зручність з мобільних пристроїв. | Висуває жорсткі вимоги до **Time Behaviour**, **Fault Tolerance** (збереження прогресу тесту) та адаптивного **UI/Usability**. |
| **End User (Викладач)** | Науково-педагогічний працівник | Швидке заповнення журналу для великих потоків студентів, захист тестів від списування, коректний розрахунок підсумкових балів. | Впливає на проєктування транзакційної цілісності даних (**Integrity**) та оптимізацію масових операцій запису в БД. |
| **Administrative Staff** | Працівник деканату / методист | Швидкий пошук та погодження заяв, формування офіційних відомостей, аудит змін оцінок у журналі. | Вимагає ролей доступу (**RBAC**), незмінного журналу аудиту (**Accountability**) та модулів експорту документів (PDF/XLSX). |
| **Business Owner** | Керівництво університету / ректорат | Помірна вартість інфраструктури (оптимальне використання власних серверів або бюджетного хмарного хостингу), швидкий запуск MVP. | Визначає вибір архітектурного стилю (**Modular Monolith**) замість дорогої в обслуговуванні мікросервісної інфраструктури. |
| **DevOps / SysAdmin** | Інженер ІТ-відділу університету | Простота розгортання та оновлення, централізований збір логів і метрик, автоматичне резервне копіювання БД. | Висуває вимоги до контейнеризації (**Docker**), моніторингу (**Observability**) та автоматичного відновлення (**Recoverability**). |
| **Security Officer** | Фахівець із захисту інформації | Захист персональних даних студентів і викладачів, запобігання несанкціонованій зміні оцінок, відповідність вимогам законодавства про захист ПД. | Визначає впровадження **OAuth2 / OIDC**, шифрування трафіку (**TLS 1.3**), хешування паролів і сувору ізоляцію прав доступу. |
