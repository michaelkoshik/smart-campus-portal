# 2. Специфікація нефункціональних вимог (ISO/IEC 25010:2023)

## 2.1. Перелік нефункціональних вимог (NFR)

У таблиці нижче наведено деталізовані нефункціональні вимоги для системи **Smart Campus & Educational Portal**, класифіковані відповідно до моделі якості продукту **ISO/IEC 25010:2023**.

| ID | Категорія (ISO 25010:2023) | Підхарактеристика | Конкретизована нефункціональна вимога | Кількісний індикатор / Метрика |
| :--- | :--- | :--- | :--- | :--- |
| **NFR-01** | **Performance Efficiency** (Продуктивність) | Time Behaviour | Швидкість завантаження розкладу занять та електронного журналу для студента або викладача. | Latency **p95 ≤ 150 ms**, **p99 ≤ 300 ms** при навантаженні до 1 000 RPS. |
| **NFR-02** | **Performance Efficiency** (Продуктивність) | Capacity | Пропускна здатність модуля онлайн-тестування під час одночасного складання модульного контролю великим потоком студентів. | Система повинна стабільно обробляти піково **2 500 RPS** (збереження відповідей тесту) з часткою помилок `5xx` **< 0.01%**. |
| **NFR-03** | **Reliability** (Надійність) | Availability | Коефіцієнт безперервної доступності порталу протягом навчального семестру та екзаменаційної сесії. | **SLA ≥ 99.9%** (допустимий сумарний час простою не більше **8.76 годин на рік** або ~43 хв на місяць). |
| **NFR-04** | **Reliability** (Надійність) | Fault Tolerance & Recoverability | Збереження прогресу проходження онлайн-тесту та відновлення працездатності сервісу після збою. | **RPO = 0** (нульова втрата відповідей студентів при перезапуску контейнера); **RTO ≤ 2 хвилин** для автоматичного перезапуску сервісу. |
| **NFR-05** | **Security** (Безпека) | Confidentiality | Захист персональних даних студентів/викладачів (РНОКПП, контакти, облікові дані) під час передавання та зберігання. | Шифрування трафіку протоколом **TLS 1.3**; шифрування чутливих полів у БД за алгоритмом **AES-256**; хешування паролів через **Argon2id**. |
| **NFR-06** | **Security** (Безпека) | Integrity & Accountability | Захист оцінок у журналі та результатів тестування від несанкціонованої модифікації та фіксація всіх змін. | **100%** операцій зміни оцінок або статусів заяв фіксуються у незмінному (append-only) Audit Log із зазначенням `user_id`, IP-адреси та `timestamp`. |
| **NFR-07** | **Maintainability** (Підтримуваність) | Modularity & Testability | Висока тестованість та ізольованість бізнес-логіки модулів (розклад, журнал, тести, заяви) для безпечного розвитку. | Покриття шару бізнес-логіки (**Domain / Use Cases**) автоматизованими юніт-тестами **≥ 80%**; цикломатична складність методів **≤ 10**. |
| **NFR-08** | **Flexibility** (Гнучкість) | Scalability | Горизонтальне масштабування безстатусних (stateless) екземплярів застосунку в періоди пікового навантаження (початок семестру, сесія). | Автоматичне розгортання додаткових реплік контейнерів (Horizontal Pod / Container Autoscaling) при завантаженні **CPU > 70%** або **RAM > 80%** протягом **2 хвилин**. |
| **NFR-09** | **Interaction Capability** (Взаємодія та зручність) | Appropriateness Recognizability & User Error Protection | Зручність інтерфейсу на мобільних пристроях та захист студента від випадкової втрати заповненої заяви чи відповіді на тест. | Показник **Google Lighthouse Accessibility & Best Practices ≥ 90/100**; підтвердження критичних дій (завершення тесту, відкликання заяви) та автозбереження чернеток кожні **10 секунд**. |

## 2.2. Пріоритетні архітектурні драйвери (Architectural Drivers)
На основі специфікації NFR виділено 4 ключові архітектурні драйвери, які безпосередньо визначають вибір архітектурного стилю, баз даних та механізмів безпеки на наступних етапах проєктування:
1. **Висока конкурентність запису під час пікових навантажень** (`NFR-02`, `NFR-08`) — одночасна робота тисяч студентів під час онлайн-тестування та перегляду розкладу в перші тижні навчання.
2. **Цілісність та непідробність академічних даних** (`NFR-06`) — сувора транзакційність журналу оцінок та повна підзвітність дій викладачів і адміністрації.
3. **Відмовостійкість процесу оцінювання** (`NFR-04`) — гарантія збереження відповідей студента навіть за короткочасних розривів зв'язку чи збоїв інфраструктури.
4. **Модульність і швидкість розробки** (`NFR-07`) — чітке розділення доменів (Schedule, Gradebook, E-Requests, Assessment) для зручної підтримки невеликою командою.
